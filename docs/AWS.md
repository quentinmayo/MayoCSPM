# AWS onboarding

AWS connections use temporary STS credentials, an exact role ARN and a unique
external ID generated by this instance. Static access keys are not accepted or
stored by the connection API. Follow
[AWS's third-party role guidance](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_common-scenarios_third-party.html).

1. Provide an operator identity to the **worker only**. Prefer an EC2 instance
   profile, ECS task role, or Kubernetes workload identity. Its policy should
   allow `sts:AssumeRole` only on your chosen collector roles. The operator role
   should not be an administrator or have workload/data access.
2. In Connections, create an AWS connection with the intended collector ARN,
   for example `arn:aws:iam::123456789012:role/MayoCSPMReadOnly`, and select the
   regions/services and budgets. The account ID must be your own target account.
3. Copy the generated `mc-…` external ID. It is a trust-policy binding, not an AWS
   secret. Each connection gets a different ID.
4. Deploy [read-only-role.yaml](../deploy/aws/read-only-role.yaml) in that target
   account with your exact **OperatorRoleArn**, **ExternalId**, and the matching
   **CollectorRoleName** (default `MayoCSPMReadOnly`). The template requires
   `CAPABILITY_NAMED_IAM`. It does not create EC2, EKS, databases, snapshots, buckets
   or other chargeable workloads. Review its role permissions before deployment.
5. Grant the operator permission to assume the resulting role. In the platform,
   choose **Validate & scan**. The first validation must fail when the external
   ID is missing or incorrect and succeed with the correct ID. Other errors,
   including denied validation, fail closed.
6. Review Scan history → Coverage. A successful trust test does not guarantee
   every collector permission is available. Service denials remain unknown. After
   validation, choose a collection interval or leave the connection manual.

The self-hosted operator role can be in the same AWS account as the collector.
An IAM user profile cannot substitute for an exact role principal in this
template; use a reviewed operator role chain. Do not broaden the trust principal
to account root or wildcard simply to make an onboarding error disappear.

## Non-AWS worker

Use a short-lived, private AWS operator profile and the
[credential overlay](../deploy/compose.aws-credentials.yaml). The file is mounted
read-only into the worker, not the app. The host file must be readable by the
worker UID 10001; provision a dedicated file/directory with appropriate ownership,
not a broad mount of your personal `~/.aws` directory.

```sh
# Set AWS_CREDENTIALS_FILE and AWS_PROFILE in private .env first.
docker compose -f compose.yaml -f deploy/compose.aws-credentials.yaml up -d --wait
```

Refresh session credentials before they expire. MFA/OIDC-backed AWS profiles may
require external refresh; the app does not collect an AWS console password or
automatically renew interactive logins. On EC2, set `AWS_EC2_METADATA_DISABLED=false`
only for the worker and configure IMDSv2 access with an appropriate container hop
limit through your infrastructure provisioning.

## Supported inventory and intentional gaps

Collectors cover EC2 instances/security groups/volume metadata, general-purpose
S3 buckets, RDS DB instances, account MFA/count metadata, multi-region CloudTrail
logging presence, and EKS configuration. Aurora cluster-specific settings,
directory buckets, IAM permission paths, network routes/NACLs, ELB/API Gateway,
Lambda, ECR contents, and other services are not covered.

S3 bucket safeguards combine account and bucket settings conservatively. Unknown
account configuration can prevent a conclusive safeguard result; effective
organization policy is not independently retrieved. Policy classification and
RestrictPublicBuckets are configuration evidence, not an object-access test.

CloudTrail's starter rule checks logging multi-region presence. It does not verify
management-event selectors, organization coverage, log integrity or delivery.
Posture references are guidance, not exact implementation of every referenced
Security Hub control or a certified compliance assessment.

## Local read-only export

For an operator-controlled diagnostic, the local CLI can use the standard AWS SDK
credential chain without creating a platform connection. It writes a **new mode
600 file** and prints only aggregate counts. Keep real inventory outside Git.

```sh
PYTHONPATH=. .venv/bin/python scripts/scan-aws.py \
  --region us-east-1 --max-resources 100 --max-api-calls 100 \
  --output /private/operator/path/inventory.json
```

This CLI path does not exercise cross-account role onboarding and is not a
substitute for that validation. It issues only the implemented metadata reads.
